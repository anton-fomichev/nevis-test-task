# Decision register

One row per decision. Rows 1–20 come from the design review done before coding started (see
`docs/PROMPT.md`, section 3); rows from 21 on were added while building. Each row says what was
decided, what else was on the table, why, and what would make us revisit it.

| #   | Area          | Decision                                                                                                                                                                                                         | Alternatives considered                                                                                                    | Why                                                                                                                                                                                                           | Revisit when                                                                                                |
| --- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1   | Repo          | Monorepo with npm workspaces: `apps/web`, `apps/api`, `packages/contracts`. One `npm install`; `npm run dev` starts both apps via `concurrently`; Vite proxies `/api`. Node 22.                                  | pnpm + turborepo; two separate repos; single Vite app with a mock server.                                                  | npm workspaces need zero extra tooling and reviewers can run it with what they already have. A real REST API was required, so two apps; the shared boundary needs a home.                                     | The team standardises on pnpm, or build times justify a task runner.                                        |
| 2   | Contracts     | `packages/contracts` holds zod schemas and the inferred TS types of the API response. The API validates against them in tests; the web parses responses with them.                                               | Hand-written TS interfaces shared by path; OpenAPI codegen; no sharing at all.                                             | One source of truth for the wire shape with runtime validation on the consumer side — a malformed payload fails loudly in the UI instead of rendering `NaN`.                                                  | The API grows enough to justify OpenAPI + generated clients.                                                |
| 3   | API           | Fastify 5 + TypeScript, run with `tsx`. `GET /api/clients` → `{ months, company }`; `GET /api/health`. Payload stored byte-for-byte from the brief in `apps/api/src/data/clients.json`.                          | Express; Hono; Next.js route handlers; json-server.                                                                        | Fastify is fast, typed, has first-class `inject()` for tests and no legacy baggage. Keeping the JSON file verbatim makes "served unchanged" checkable with a diff.                                            | A database or auth shows up.                                                                                |
| 4   | API           | Dev-only query params `?delay=<ms>` and `?fail=1` to demo loading/error states; ignored when `NODE_ENV=production`.                                                                                              | Hard-coded artificial latency; a separate mock endpoint; MSW in the browser.                                               | Reviewers can reach every UI state from the address bar without touching code, and production cannot be tripped by them.                                                                                      | A real staging environment makes them unnecessary.                                                          |
| 5   | Web           | Vite + React 19 + TypeScript strict. Data fetching with TanStack Query. No global state library; expanded-row state is a `Set<string>` in `useReducer` local to the table.                                       | Next.js; SWR; plain `useEffect` + fetch; Redux/Zustand for expanded state.                                                 | Query gives loading/error/retry/caching with the idioms real teams use. Expanded state has exactly one consumer, so lifting it would be ceremony.                                                             | Expanded state must be shared (URL sync, chart driven by selected row).                                     |
| 6   | Styling       | CSS Modules + CSS custom properties for tokens (`app/tokens.css`). Inter via `@fontsource-variable/inter`. No Tailwind, no UI kit.                                                                               | Tailwind; vanilla-extract; styled-components; MUI/Chakra.                                                                  | Pixel-matching a Figma spec is easiest with plain CSS; modules give scoping for free; tokens keep the palette in one file (and make dark mode a later token swap).                                            | A design system package exists to consume.                                                                  |
| 7   | Chart         | Hand-rolled SVG. Layout is a pure function `buildStackedLayout(series, months, {height, tickCount})` returning segments/ticks/scale; the component is a thin renderer over it.                                   | Recharts; Nivo; visx; Chart.js; D3 for scales only.                                                                        | Exact match to the design (clipped rounded columns, dashed grid), full control over a11y markup, and the "data → chart mapping" test the brief asks for becomes a unit test on a pure function.               | Tooltips, animations or more chart types are requested — then visx or D3 scales.                            |
| 8   | Testing       | Vitest + React Testing Library + user-event + jest-dom (web); Vitest + `app.inject()` (API); `vitest --coverage` wired, no threshold. No Playwright.                                                             | Jest; Playwright component tests; Cypress.                                                                                 | Vitest shares Vite's config and is fast; RTL + user-event test what the user does. E2E is the first "next step", not a day-one requirement for a 6–8h task.                                                   | A CI budget exists for browser tests.                                                                       |
| 9   | Tooling       | ESLint flat config (typescript-eslint, react-hooks, jsx-a11y) + Prettier. Root scripts `dev`, `build`, `test`, `lint`, `typecheck`, `format`.                                                                    | Biome; no linter.                                                                                                          | jsx-a11y catches the a11y mistakes a reviewer would look for first; Prettier removes style from code review.                                                                                                  | Biome reaches parity on React a11y rules.                                                                   |
| 10  | Web structure | Feature-first, shallow: `app/`, `shared/ui`, `shared/lib`, `features/clients/{api,model,ui}`. Components take data and callbacks and never fetch; the dashboard composes them.                                   | Atomic design folders; co-locating everything under `components/`.                                                         | Keeps the one feature readable and the shared bits obviously shared; props are the component API a team would consume.                                                                                        | A second feature appears.                                                                                   |
| 11  | Accessibility | WAI-ARIA treegrid: `<table role="treegrid">`, rows carry `aria-level/posinset/setsize`, `aria-expanded` only when they have children. The row is the interactive element (roving tabIndex).                      | Nested `<ul>` tree + separate columns; a `<button>` in the name cell; disclosure widgets per row.                          | The treegrid pattern is the ARIA-sanctioned shape for "a table whose rows expand". Row-level interaction matches the design's whole-row click target.                                                         | Screen-reader testing shows users prefer a discoverable button (see #19).                                   |
| 12  | Accessibility | Keyboard map: ↑/↓ move, → expands or moves to first child, ← collapses or moves to parent, Enter/Space toggle, Home/End first/last. Collapsed children are not rendered.                                         | Tab through every row; only Enter/Space.                                                                                   | This is the APG treegrid key map; not rendering collapsed children keeps the DOM honest for AT.                                                                                                               | Column-level cell navigation is required.                                                                   |
| 13  | Accessibility | Chart: `role="img"` with a summarising `aria-label` plus a visually-hidden `<table>` carrying the same numbers.                                                                                                  | `aria-describedby` on every rect; no hidden table (the main table has the numbers anyway).                                 | A single label for the picture and a real table for the data is the pattern AT users expect; it does not depend on the main table being adjacent.                                                             | The chart becomes interactive (tooltips, selection).                                                        |
| 14  | Responsive    | ≤768px: both cards `overflow-x: auto`; the name column sticks (`position: sticky; left: 0`) and shrinks to 180px; the chart keeps a min plot width of 720px.                                                     | Collapse months into a dropdown; card per month; hide columns.                                                             | The brief asks for nothing broken down to 375px, not a mobile redesign. Internal scroll keeps every number reachable without page-level overflow.                                                             | Mobile becomes a first-class target.                                                                        |
| 15  | Model         | Normalise `branches/employees/channels` into one `TreeNode { id, name, kind, values, children }` at the feature boundary. Rows without children are not expandable.                                              | Keep the three key names in the components; a generic `children` key in the API.                                           | Table and chart code should not know about three key names; the API stays verbatim to the brief.                                                                                                              | The API gains a uniform `children` key.                                                                     |
| 16  | Q1            | Branch 2 / Branch 3 have no employees but the mockup draws chevrons on them. No chevron, no `aria-expanded`, not interactive; name indented to align with Branch 1.                                              | Render a disabled chevron; render an empty expanded state.                                                                 | A control that does nothing is worse than none. We read the Figma chevrons as a mockup oversight and say so in the README.                                                                                    | The data gains employees there, or the designer confirms the chevron is intentional.                        |
| 17  | Q2            | The legend in the design shows acquisition channels, but only Anna Blackwood has channel data. The chart stacks the Company by its branches; legend = branch names; three series colours.                        | Stack by channel with an "Unattributed" bucket (~90% of every bar); show only Anna's channels.                             | Stacking by channel would hide the information behind one huge bucket. Branch breakdown uses the data that exists. `StackedBarChart` is data-agnostic so switching is a one-line change.                      | Channel data exists for every adviser, or a row-driven breakdown is requested.                              |
| 18  | Q3            | Children do not always sum to their parent (Company May 2024 = 301 vs 279; Branch 1 Aug 2024 = 214 vs 216; Anna May–Sep ±1–2; Maria May 2024 = 22 looks like a typo). Payload wins.                              | Recompute parents from children; flag mismatches in the UI.                                                                | The API is the source of truth; silently "fixing" data is how finance dashboards lose trust. A unit test documents each known mismatch so the next person sees it.                                            | The data owner confirms the intended rule (sum vs. independent figures).                                    |
| 19  | Q4            | Figma mockups disagree with the payload (Branch 1 Jul 2024 = 291 in Figma; Robert Chen Aug 2024 = 56; "New paid" row order). Payload wins; noted in README.                                                      | Match the mockup numbers by hand.                                                                                          | The mockup is illustration; the payload is the contract.                                                                                                                                                      | Never — unless the payload changes.                                                                         |
| 20  | Q5            | Advisers have photo avatars in the design; the payload has none. `Avatar` renders initials on a deterministic colour derived from the node id. API not extended with fake URLs.                                  | Fake image URLs in the API; a generic user icon.                                                                           | Initials are honest about the data we have and still read as the design. Faking fields in the API would blur the "payload unchanged" promise.                                                                 | `avatarUrl?: string` lands on adviser nodes.                                                                |
| 21  | Q6            | Months are not in the payload. The API returns `months` as ISO `YYYY-MM` strings next to the tree; the UI formats them for display. The API asserts every node has `values.length === months.length` at startup. | Hard-code month labels in the UI; put labels in the JSON file.                                                             | The server knows what the figures mean; the client should not guess. The assertion turns a silent misalignment into a startup failure.                                                                        | The API gains per-row date ranges.                                                                          |
| 22  | Q7            | Y-axis range computed from data: nice max = `ceil(max/100)*100`, 5 ticks. Design hard-codes 0–400, which is what the current data produces.                                                                      | Hard-code 400; nicer "1/2/5" tick algorithm.                                                                               | Data-driven axes survive new data; the simple rule reproduces the design exactly for this payload.                                                                                                            | Values get much larger/smaller than hundreds.                                                               |
| 23  | Q8            | When a parent collapses, its descendants keep their expanded state (the id set is not pruned).                                                                                                                   | Prune descendants on collapse.                                                                                             | Re-expanding restores the previous view; cheapest and least surprising.                                                                                                                                       | Trees get large enough for the set to matter.                                                               |
| 24  | Q9            | Whole row is the click/keyboard target, per the design and the treegrid pattern.                                                                                                                                 | A `<button>` in the name cell.                                                                                             | Matches the design's click target and the APG pattern. Trade-off: a nested button is more discoverable for screen-reader users who browse by form controls — noted in README.                                 | SR user testing says otherwise.                                                                             |
| 25  | Q10           | No hover background and default cursor on leaf rows.                                                                                                                                                             | Hover on every row.                                                                                                        | Hover signals "clickable"; leaves are not.                                                                                                                                                                    | Rows gain other actions (links, menus).                                                                     |
| 26  | Q11           | No "selected row drives the chart" behaviour; chart shows the company by branch (see #17).                                                                                                                       | Clicking a row re-stacks the chart by that row's children.                                                                 | Not in the design; listed as the first next step because the chart is already data-agnostic.                                                                                                                  | Product asks for drill-down in the chart.                                                                   |
| 27  | Q12           | The first header cell reads "Placeholder" in white in Figma. Render a visually-hidden "Name" header so AT gets a column name.                                                                                    | Empty `<th>`; visible "Name".                                                                                              | An empty header is an a11y smell; a visible one deviates from the design.                                                                                                                                     | Design adds a real header.                                                                                  |
| 28  | Tooling       | Pin TypeScript 5.9, ESLint 9, Vite 7, Vitest 4, React 19 rather than the registry's newest majors (TS 7, ESLint 10, Vite 8, Vitest 5).                                                                           | Latest everything.                                                                                                         | Known-compatible set across plugins, RTL and jsdom; a timed task is not the place to debug a new major.                                                                                                       | The ecosystem catches up with the new majors.                                                               |
| 29  | Tooling       | Vitest 4.1.12 installed once with `--legacy-peer-deps` to dodge an npm 10.9 resolver crash on jsdom's optional `canvas` peer; the committed lockfile makes plain `npm install`/`npm ci` work.                    | Stay on Vitest 4.0 (two audit findings); add `legacy-peer-deps=true` to `.npmrc` for everyone.                             | Zero audit findings for reviewers running `npm audit`, without changing peer semantics for the whole repo. Only someone _adding_ a dependency with that npm version needs the flag.                           | npm fixes the arborist bug, or the team upgrades npm.                                                       |
| 30  | Formatting    | Month labels use `Intl.DateTimeFormat('en-US', { month: 'short', year: 'numeric', timeZone: 'UTC' })`.                                                                                                           | `en-GB` (renders "Sept 2024"); hard-coded label array.                                                                     | The design shows "Sep 2024"; both locales put month before year, so `en-US` matches the design while staying locale-driven.                                                                                   | The product gets real i18n.                                                                                 |
| 31  | Contracts     | One zod schema per tree level (channel/employee/branch/company) extending a shared base, instead of a single recursive schema.                                                                                   | One recursive node schema with optional `branches`/`employees`/`channels` on every level.                                  | The three child keys differ per level; per-level schemas make the inferred types exact (a company cannot carry `channels`) at the cost of ~10 lines.                                                          | The API switches to a uniform `children` key.                                                               |
| 32  | Contracts     | Package `exports` → `dist/`; apps alias `@nevis/contracts` → `src/` via tsconfig `paths` + Vite alias, so dev/test/typecheck see source and only production builds consume `dist/`.                              | Point `exports` at `src/` (breaks the built API at runtime); build on `postinstall`.                                       | No stale-`dist` footguns while developing; the production build still has a real, type-declared artefact.                                                                                                     | Node's type stripping makes `.ts` exports viable, or a bundler is added to the API.                         |
| 33  | API           | No CORS middleware; the web reaches the API through Vite's `/api` proxy in dev and would share an origin (or sit behind a gateway) in production.                                                                | `@fastify/cors` with `origin: true`.                                                                                       | One fewer dependency and no permissive-CORS default to forget about later.                                                                                                                                    | The web is deployed on a different origin from the API.                                                     |
| 34  | API           | Listen on `127.0.0.1:3001`; the Vite proxy targets `http://127.0.0.1:3001` explicitly.                                                                                                                           | `localhost` on both sides; `0.0.0.0`.                                                                                      | Node ≥17 may resolve `localhost` to `::1`; naming the IPv4 address on both sides removes a classic "proxy ECONNREFUSED" footgun.                                                                              | The API must be reachable from other machines (then `HOST=0.0.0.0`).                                        |
| 35  | Tooling       | `vite@^7` is declared at the root as well as in `apps/web`, so npm hoists one copy that Vitest, `@vitejs/plugin-react` and the app all dedupe to.                                                                | Let Vitest pull its own Vite (ended up with Vite 8 next to Vite 7 → broken react-refresh).                                 | A single Vite instance is the only configuration the plugin ecosystem tests; the duplicate cost a blank page and twenty minutes.                                                                              | The app moves to Vite 8 (then drop the root pin or bump both).                                              |
| 36  | API           | The API reads `API_PORT`/`API_HOST`, not `PORT`/`HOST`.                                                                                                                                                          | Generic `PORT`.                                                                                                            | Dev tooling and PaaS runtimes commonly export `PORT` for _the_ web process; a namespaced variable keeps the API from binding to the web server's port by accident.                                            | The API is deployed as its own process on a platform that injects `PORT` (then map it in the start script). |
| 37  | Chart         | `buildStackedLayout` computes vertical geometry only (`y`, `height`, ticks, scale). Columns are flex items; each column is drawn in its own small SVG, grid lines in one background SVG.                         | One full-width SVG with measured x positions (`ResizeObserver`); `preserveAspectRatio="none"`.                             | Matches the design's `flex: 1` columns literally, needs no measurement (works in jsdom), and keeps the layout a pure function. The stretch approach would distort the 4px radii.                              | Tooltips/brush selection need a single coordinate space.                                                    |
| 38  | Accessibility | `table role="treegrid"` keeps a one-element jsx-a11y exception; native `th scope` provides `columnheader`/`rowheader`; `td` carries an explicit `role="gridcell"` as in the APG example.                         | Rebuild the grid from `div`s with explicit roles everywhere; drop the linter rule globally.                                | A real `<table>` keeps native semantics, column sizing and copy/paste; the single suppression is documented where it lives, and the explicit gridcell role survives tools that skip HTML-AAM context mapping. | jsx-a11y learns the treegrid pattern.                                                                       |
| 39  | Chart         | The legend is a labelled `<ul>` rendered _outside_ the `role="img"` element; the hidden data table sits next to it.                                                                                              | Legend inside the image (silent for AT); legend as the only textual alternative.                                           | Series names are text, not picture; keeping them outside the image means AT hears them in the place sighted users read them, and the table carries the numbers.                                               | The chart becomes interactive and needs per-segment semantics.                                              |
| 40  | Web           | The Retry button drops the forwarded dev flags (`?delay`, `?fail`) before refetching.                                                                                                                            | Replay the same request (never recovers while `?fail=1` is in the URL); make `fail` one-shot on the server (stateful API). | The flags simulate a failing server; Retry should demonstrate recovery, and the API stays stateless. Behaviour is dev-only by construction (the flags are ignored in production).                             | A real failure-injection tool replaces the flags.                                                           |
| 41  | Web           | Query retry policy (`retry: 1`) lives on the app's `QueryClient`, not in `useClientsReport`.                                                                                                                     | Per-query `retry` in the hook.                                                                                             | Tests inject their own client with retries off and get instant error states; production timing is in one place.                                                                                               | Different queries need different policies.                                                                  |
